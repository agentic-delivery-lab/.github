# Security policy

Please do not disclose suspected vulnerabilities in public issues, pull
requests, discussions, chat messages, or other public channels.

## Report privately

Report a suspected vulnerability through the affected repository's **Security**
tab and its private vulnerability-reporting channel. Choose **Report a
vulnerability** or the equivalent private reporting option and include:

- a short description of the issue and its potential impact;
- the affected repository, component, version, or configuration;
- safe steps to reproduce the behavior;
- relevant logs or proof of concept with secrets and personal data removed; and
- any mitigation or remediation context that may help the maintainers.

Use the security reporting channel for the repository that is affected. This
organization-wide policy cannot determine the repository's response process,
supported versions, or disclosure timeline; the repository maintainers will
coordinate those details through the private report.

If the Security tab or private reporting channel is temporarily unavailable,
contact the repository maintainers through a private channel documented by that
repository. Do not create a public report to work around an unavailable
channel.

## Responsible reporting

Give maintainers a reasonable opportunity to investigate and address the issue
before sharing vulnerability details publicly. Do not access, alter, or retain
data that does not belong to you. Stop testing if you encounter real user data
or service disruption, and describe the observation privately to the
maintainers.
